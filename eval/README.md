# Оценка

Корпус, метрики и harness. Всё работает офлайн: хеш-эмбеддер, хранилище в памяти,
экстрактивный генератор — ни модели, ни GPU, ни Postgres.

```bash
make bench                 # три сравнения + eval/results.json
make eval                  # один прогон текущего CONFIG
make dataset               # пересобрать корпус из семени
```

## Корпус

Вымышленная документация вымышленной платформы событий Kestrel. Третьих датасетов нет,
поэтому репозиторий целиком распространяемый.

| файл | содержимое |
|---|---|
| `datasets/corpus.jsonl` | 27 документов, 25 131 символ: 15 «настоящих» + 12 соседних сервисов-дистракторов |
| `datasets/questions.jsonl` | 106 вопросов с ответом и gold-диапазоном `(doc_id, start, end)` |
| `datasets/unanswerable.jsonl` | 8 вопросов, ответа на которые в корпусе нет |
| `datasets/generate.py` | генератор; `python -m eval.datasets.generate` воспроизводит файлы побайтово |

Факт авторится один раз — предложением и вопросами, на которые оно отвечает. Сборщик
кладёт предложение в секцию документа, gold-разметкой становится его символьный
диапазон в готовом тексте. Отсюда два свойства:

- **разметка не может разойтись с текстом** — она вычисляется из него;
- **разметка чанкер-независима** — harness превращает диапазон в множество
  перекрывающихся чанков для той нарезки, которая тестируется, поэтому четыре стратегии
  сравниваются по одним и тем же меткам.

Генератор падает, если gold-предложение встречается в документе не ровно один раз, и
если документ-дистрактор повторил gold-предложение. `tests/test_datasets.py` проверяет,
что закоммиченные JSONL совпадают с выводом генератора.

Дистракторы нужны для того, чтобы таблица что-то различала: без них `recall@5` упирается
в 1.0 у любой конфигурации. Они намеренно используют тот же словарь — порт, квота,
retention, реплики, журнал — но не содержат ни одного gold-ответа.

## Метрики

| метрика | что считает | о чём говорит |
|---|---|---|
| `recall@k` | доля релевантных чанков в топ-k | попал ли ответ в контекст вообще |
| `precision@k` | доля топ-k, которая релевантна | размывание контекста: сколько шума уходит в модель |
| `MRR` | 1 / ранг первого попадания | насколько высоко ответ |
| `nDCG@k` | бинарный gain с логарифмическим дисконтом | то же, но с учётом всех попаданий |
| `faithfulness` | доля терминов ответа, встречающихся в процитированных чанках | лексический прокси заземлённости |
| `answer_terms` | доля терминов эталонного ответа в выданном | регрессионный сигнал по содержанию |
| `refused_*` | доля отказов на отвечаемых / неотвечаемых | цена и польза порога `min_support` |

`precision@k` здесь мала по построению: релевантных чанков один-два, поэтому потолок —
`len(relevant) / k`. Смотреть на неё надо как на меру разбавления контекста, а не как на
оценку поиска.

`faithfulness` с экстрактивным генератором равна 1.000 по построению. Полезна она не
значением, а тем, что harness падает, если хоть один ответ сослался на чанк, которого
не было в выдаче: структурная гарантия цитат проверяется на каждом прогоне, а не
предполагается.

## Harness

`evaluate()` строит конвейер из конфига, индексирует корпус, прогоняет все вопросы и
возвращает строку таблицы. Варианты собираются мутацией конфига (`variant()`), а не
отдельными пайплайнами — поэтому в сравнении не может случайно разъехаться ничего,
кроме того, что сравнивается.

Три сравнения:

1. **чанкинг** — четыре стратегии при одинаковом поиске;
2. **режимы поиска** — dense, BM25, RRF, min-max, RRF + реранкер, при чанкере-победителе
   первого сравнения;
3. **порог поддержки** — `generation.min_support` от 0.00 до 0.67, ложные и верные
   отказы.

Результаты и их разбор — в корневом [README](../README.md#бенчмарк). Там же названо,
что этими числами можно мерить, а что нельзя.
